PHASE 1 Session Setup
ARJUN (Host)
REST →
POST /sessions — creates the game room
Arjun enters his name and taps "Create Game".
Flutter sends: { host_id, display_name, total_rounds: 5 }
Server creates a session in memory, generates a short room code (e.g. "XKQZ").
Returns: { session_id, room_code } — Arjun's phone shows the code to share.
ARJUN (Host)
SSE ←
Opens SSE stream — now receives all game events
Flutter opens a long-lived HTTP GET to /sessions/{id}/events?playerId=arjun.
Server registers Arjun's connection in session.connections Map.
Server sends ": connected" comment to confirm stream is live.
This connection stays open for the entire game. No re-connecting needed between rounds.
BHANU (P1)
REST →
POST /sessions/join — joins by room code "XKQZ"
Bhanu types the room code on his phone and taps "Join".
Flutter sends: { room_code: "XKQZ", player_id, display_name: "Bhanu" }
Server finds the session, adds Bhanu to session.players Map.
Returns: full session snapshot { session_id, session: { players, phase, ... } }
Bhanu's Flutter app builds its initial state from this snapshot.
BHANU (P1)
SSE ←
Opens SSE stream — now in the game loop
Bhanu's Flutter app opens its own SSE connection immediately after joining.
Server registers his connection. Now session.connections has 2 entries.
Server broadcasts PLAYER_JOINED to Arjun (not Bhanu — he already knows himself).
Arjun's lobby screen updates to show "Bhanu joined".
CHARU (P2)
REST →
POST /sessions/join — joins by room code "XKQZ"
Same as Bhanu's join. Charu is added to session.players.
Server broadcasts PLAYER_JOINED → Arjun's and Bhanu's phones both update.
CHARU (P2)
SSE ←
Opens SSE stream — all 3 players now connected
session.connections now has 3 entries: Arjun, Bhanu, Charu.
From this point, every broadcast() call reaches all 3 phones simultaneously.
The lobby shows all 3 player names. Arjun's "Start" button is now enabled (≥2 players).
PHASE 2 Game Start
ARJUN (Host)
REST →
POST /sessions/:id/start — triggers game begin
Arjun taps "Start Game". Flutter sends: { host_id: arjun }.
Server validates: caller is host, phase is lobby, ≥2 players present.
Server shuffles questions (Fisher-Yates), selects 5 (or total_rounds count).
Sets session.phase = 'active', session.currentQuestionIndex = 0.
SERVER
SSE ←
Broadcasts GAME_START → all 3 phones
Payload: { total_rounds: 5, scoring_rules: { base: 100, max_speed: 50, streak_step: 10 } }
All 3 Flutter apps: initial → lobby (already) → now waiting for ROUND_COUNTDOWN.
GameController sets scoringRules so the UI can show the scoring legend.
SERVER
SSE ←
Broadcasts ROUND_COUNTDOWN → 3-second "Get Ready" screen
Server schedules this immediately after GAME_START (no delay).
Payload: { round_number: 1 }
All 3 phones transition to countdown phase. A 3-second visual timer runs.
The server waits 3 seconds then opens Question 1.
PHASE 3 One Question Round (repeats × 5)
SERVER
SSE ←
Broadcasts QUESTION → question appears on all 3 phones
Payload: { question_id, type: "mcq", text: "...", options: [...], timer_seconds: 15 }
Server records questionStartTime = Date.now() for speed-bonus calculation.
All 3 Flutter apps: countdown → questionActive.
A 15-second arc timer starts on each phone's screen.
ARJUN (Host)
REST →
POST /sessions/:id/answers — submits his answer (3.2s in)
Flutter sends: { question_id, player_id, answer: "Paris" }
Server records: answers.set(arjun, { answer, submittedAt: Date.now() })
Server calculates elapsed = submittedAt - questionStartTime = 3200ms.
Answer is NOT scored yet — server waits for all players or timer expiry.
SERVER
SSE ←
Broadcasts ANSWER_COUNT → live progress bar updates
Payload: { answered: 1, total: 3 }
Debounced at 500ms — if Bhanu and Charu also answer within 500ms, only one event fires.
All phones show "1/3 answered" progress bar. No answer content revealed yet.
BHANU (P1)
REST →
POST /sessions/:id/answers — submits his answer (7.1s in)
Bhanu taps an answer. Flutter records this and submits.
Server now has 2/3 answers. ANSWER_COUNT debounce fires: { answered: 2, total: 3 }.
CHARU (P2)
REST →
POST /sessions/:id/answers — submits her answer (9.4s in)
All 3 players have now answered. Server detects 3/3 — closes question early.
(No need to wait for the 15-second timer to expire.)
Server calculates scores for all 3 players simultaneously.
SERVER
SSE ←
Sends Q_RESULT individually to each player (3 separate sends)
This is NOT a broadcast — each player gets their own private result.
Arjun: { correct_answer: "Paris", is_correct: true, score_delta: 147, speed_bonus: 47, streak_bonus: 0 }
Bhanu: { correct_answer: "Paris", is_correct: true, score_delta: 130, speed_bonus: 30, streak_bonus: 0 }
Charu: { correct_answer: "Paris", is_correct: false, score_delta: 0, ... }
Each phone shows: correct answer highlighted + personal score breakdown banner.
SERVER
SSE ←
Broadcasts LEADERBOARD → standings shown on all phones
Payload: { round_number: 1, top_players: [{ player_id, display_name, total, rank, rank_delta, streak }] }
rank_delta = how many positions each player moved vs last round.
All 3 phones transition to leaderboard phase and show the ranked list.
After 5 seconds, server sends ROUND_COUNTDOWN for round 2 and loop repeats.
PHASE 4 Game End
SERVER
SSE ←
Broadcasts GAME_END → final screen on all phones
After round 5 LEADERBOARD, server detects currentQuestionIndex = totalRounds.
Broadcasts: { final_leaderboard: [...], winner_player_id: "arjun" }
All 3 phones transition to gameEnd phase — final leaderboard with trophy icon shown.
Host sees "Play Again" and "Leave" buttons. Players see "Leave" only.
ARJUN (Host)
REST →
POST /sessions/:id/restart (optional) — plays again
Arjun taps "Play Again". Flutter sends: { host_id: arjun }.
Server: cancels the 60s cleanup timer, resets all scores + answers + questionIndex.
Keeps same players and SSE connections — no reconnection needed.
Broadcasts GAME_RESTARTED → all phones reset to lobby phase cleanly.

The entire game state for one session lives in a single JavaScript object in RAM. No disk, no database.
